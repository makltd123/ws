# ws: контекстные рабочие пространства для Windows

[English version](README.md)

`ws` описывает проект как *пространство*: какие приложения открыть, с какими папками, в каких позициях окон. Умеет запускать пространство из YAML-манифеста, привязывать новые окна к нему, расставлять их, снимать текущую раскладку (`ws save`) и переключаться между пространствами: окна уходящего прячутся, а его процессы замораживаются (suspend). Трей, горячие клавиши и заметки «где я остановился» (этапы 4-5 в [SPEC.md](SPEC.md)) пока не сделаны.

Это **не** замена виртуальным рабочим столам Windows, их внутренний API не используется.

## Установка

```
uv sync
uv run ws doctor
```

## Команды

```
ws list                # пространства и их статус
ws edit <имя>          # открыть манифест (или создать из шаблона) в $EDITOR / блокноте
ws open <имя>          # запустить пространство или вывести его окна вперёд, если уже запущено
ws open .              # запустить .workspace.yml текущего репозитория (и запомнить его по имени)
ws hook show|install|uninstall   # необязательный хук PowerShell для заметок «где я остановился»
ws save <имя>          # снять раскладку текущих видимых окон в новый манифест (--force перезапишет, старый останется как .bak)
ws switch <имя>        # заморозить активное пространство (спрятать окна, остановить процессы), открыть или разморозить <имя>
ws freeze [<имя>]      # заморозить активное (или указанное) пространство
ws thaw <имя>          # разморозить без переключения
ws close <имя>         # попросить окна закрыться (WM_CLOSE) с подтверждением; --force предложит завершить упрямые процессы
ws tray                # значок в трее со списком пространств и глобальные горячие клавиши (--background отвязать от консоли, --stop выйти)
ws status              # что сейчас активно
ws doctor              # проверить wt, code, браузеры, DPI, права
```

Манифесты лежат в `%APPDATA%\ws\spaces\<имя>.yml`, состояние в `%APPDATA%\ws\state.json`, лог в `%APPDATA%\ws\ws.log`. Переменная `WS_HOME` задаёт другую папку (удобно для экспериментов). Формат манифеста описан в [SPEC.md](SPEC.md).

Коды возврата: 0 успех, 1 ошибка пользователя (нет такого пространства, битый манифест), 2 системная ошибка.

## Трей и горячие клавиши

`ws tray` (или `ws tray --background`, остановка `ws tray --stop`) ставит значок в область уведомлений. В меню список пространств (активное отмечено, замороженные помечены), и переключение из меню делает ровно то же, что `ws switch`. Предупреждения и ошибки приходят уведомлениями.

По умолчанию первым девяти пространствам (по алфавиту) назначаются `Ctrl+Alt+1` ... `Ctrl+Alt+9`. Свои клавиши задаются в `%APPDATA%\ws\config.yml`; если ключ есть, привязываются только перечисленные (`hotkeys: {}` отключает хоткеи):

```yaml
hotkeys:
  api-project: ctrl+alt+1
  notes: ctrl+shift+f2
```

В комбинации нужен хотя бы один модификатор (`ctrl`, `alt`, `shift`, `win`). Новые манифесты и изменения конфига подхватываются за несколько секунд, перезапуск не нужен. В автозагрузку `ws` сам себя не добавляет; если нужно, положи ярлык на `ws tray --background` в папку «Автозагрузка» сам.

## Манифест внутри репозитория

Положи в корень проекта файл `.workspace.yml` (формат тот же, что у личного манифеста, `name:` по умолчанию равен имени папки). Относительные пути в нём отсчитываются от папки файла, поэтому он работает у каждого, кто склонировал репозиторий:

```yaml
name: shop
items:
  - {type: vscode, path: .}
  - type: terminal
    tabs: [{dir: ., cmd: "npm run dev", title: dev}]
```

`ws open .` (в проекте или любой его подпапке; можно указать путь к папке или к файлу) запускает его и запоминает в `%APPDATA%\ws\repos.json`; дальше `ws switch shop`, трей и горячие клавиши знают его по имени. Личный манифест с таким же именем главнее, а `ws open .` откажется регистрировать совпадающее имя.

## Где я остановился

Когда ты уходишь из пространства (`ws switch`, `ws freeze`, трей, хоткей), `ws` сохраняет заметку: заголовок верхнего окна этого пространства и, если установлен хук ниже, последнюю команду и папку его терминалов. При возвращении `ws switch` печатает её (`↩ Ты ушёл отсюда 12 мин назад. Последнее окно: ... Последняя команда: pytest -q (в C:\proj\api).`), а трей показывает уведомление.

Последняя команда берётся из небольшого хука для PowerShell. Он **не** ставится сам:

```
ws hook show          # показывает блок и файл профиля, куда он попадёт; ничего не меняет
ws hook install       # спрашивает, делает одну резервную копию, дописывает блок в твой $PROFILE
ws hook uninstall     # убирает блок
```

`--shell pwsh` нацелен на PowerShell 7 вместо Windows PowerShell 5.1. Блок работает только в оболочках, запущенных через `ws` (проверяет переменную `WS_SPACE`, которую ставит `ws`), на каждое приглашение пишет `%APPDATA%\ws\notes\<пространство>\<pid>.json`, в остальных местах ничего не делает. При политике выполнения `Restricted` PowerShell вообще не загружает профили; `ws hook install` сообщит об этом и политику сам не меняет.

## Триггеры по ветке git

```yaml
triggers:
  git_branch: "feature/*"      # маска (* и ?), регистр важен
  repo: .                      # необязательно; по умолчанию первая папка из items
```

Пока работает `ws tray`, смена ветки git в этом репозитории на подходящую даёт уведомление и первую строку в меню трея: `→ Перейти в «shop» (ветка feature/payments)`. Только подсказка: сам `ws` ничего не переключает, и про ветку, которая уже была выбрана при запуске трея, он молчит.

## Безопасность

`ws` ничего не удаляет, не трогает реестр, автозагрузку и системные настройки, не требует прав администратора. Процесс завершается только командой `ws close --force`, после явного вопроса со списком процессов. VS Code и браузеры запускаются со своим профилем на каждое пространство (`--user-data-dir`), поэтому заморозка одного пространства не заденет другое. Чтобы использовать обычный VS Code, поставь у элемента `vscode` поле `isolate: false`.

Почему заморозка безопасна:
- Процесс замораживается, только если ни у него, ни у его потомков нет видимых окон вне этого пространства, и только после того, как его окна успешно спрятаны. Если есть сомнения, процесс остаётся работать, прячется только окно, и выводится предупреждение.
- Никогда не замораживаются: `explorer.exe` и прочие системные процессы, сам Windows Terminal (замораживаются только оболочки вкладок, которые запустил `ws`) и вся цепочка родителей запущенного `ws` (поэтому `ws switch`, набранный в терминале самого пространства, не заморозит сам себя).
- Приложения из `freeze.exclude` (в манифесте или в `%APPDATA%\ws\config.yml`) продолжают работать, их окна сворачиваются, а не прячутся.
- Всё замороженное можно вернуть: `ws doctor` покажет, `ws thaw <имя>` вернёт, перезагрузка снимает любую заморозку. Намерение записывается в `state.json` до того, как остановлен первый процесс.

## Ручной чек-лист (нужен настоящий рабочий стол Windows)

1. `ws doctor`: per-monitor DPI включён, найдены `wt`, VS Code и браузеры.
2. Создай пространство `ws edit demo` (explorer + терминал с двумя вкладками + браузер с профилем + vscode), задай позиции окон.
3. `ws open demo` на чистом столе: все окна появились на своих местах; предупреждения (если есть) выведены.
4. Ещё раз `ws open demo`: дубликатов нет, окна вышли вперёд.
5. Закрой одно окно руками, `ws open demo`: перезапускается только этот элемент.
6. Отключи второй монитор и повтори: окна встают на основной.
7. Расставь несколько окон, `ws save x`, закрой их все, `ws open x`: раскладка возвращается (адреса вкладок браузера и вкладки терминала нужно дописать в манифест руками).
8. Два пространства `a` и `b`: `ws open a`, `ws switch b`. Окна `a` исчезли, процессы остановлены (в диспетчере задач «Приостановлено», 0% CPU, `ws status` согласен). `ws switch a` возвращает всё без перезапуска приложений и намного быстрее 2 секунд.
9. `ws freeze`, затем `ws doctor` (покажет, что заморожено), затем `ws thaw a`.
10. Запусти `ws switch b` из вкладки терминала, которая принадлежит `a`: команда завершается и не замораживает сама себя.
11. `ws tray --background`, затем `Ctrl+Alt+1` / `Ctrl+Alt+2`: пространства переключаются так же, как `ws switch`. Правый клик по значку: список совпадает, активное отмечено. `ws tray --stop` убирает значок.
12. В репозитории с `.workspace.yml`: `ws open .` из подпапки; `ws list` показывает его вместе с репозиторием, а `ws switch <имя>` работает откуда угодно.
13. `ws hook install`, открой пространство с вкладкой терминала, выполни несколько команд, уйди через `ws switch` и вернись: строка `↩` называет последнюю команду и папку. `ws hook uninstall` возвращает профиль.
14. При заданном `triggers.git_branch` и запущенном `ws tray`: `git checkout -b feature/x` в репозитории даёт уведомление и строку «→ Перейти» в меню трея.

## Известные ограничения

- `env` из манифеста действует только на новые процессы. Уже запущенный VS Code или браузер его не получит.
- Вкладки терминала задаются только манифестом, из запущенного Windows Terminal их не прочитать.
- Вкладка с `cmd` запускается через `powershell.exe -NoExit -Command` (чтобы вкладка осталась открытой). Кавычки внутри `cmd` проходят через разбор самого `wt`; держи команды простыми или вынеси их в скрипт.
- `ws save` берёт **все** видимые окна, лишнее удаляй через `ws edit`. Свёрнутые окна, окна другого пространства, UWP и окна администратора пропускаются и перечисляются с причиной. Аргументы командной строки обычных приложений намеренно не сохраняются (в них бывают токены).
- `ws save` не читает открытые вкладки браузера и вкладки терминала. Папка VS Code берётся из командной строки: это работает для экземпляров, запущенных через `ws` (или `code <папка>` как первый экземпляр); обычно запущенный VS Code записывается закомментированным блоком вместе с позицией, а `path` вписываешь руками.
- Вкладки терминала, открытые руками после `ws open`, не отслеживаются: их оболочки продолжают работать при заморозке пространства (окно при этом всё равно прячется). Замораживаются только оболочки вкладок, описанных в манифесте.
- Windows Terminal может спросить подтверждение при закрытии окна с запущенными командами; тогда `ws close` сообщит, что окно не закрылось, и решение остаётся за тобой.
- Замороженный процесс может показываться в `psutil` как `running`, если несколько его потоков ждут в ядре; CPU они не тратят. Число в `ws status` это оценка.
- Замороженный процесс, владеющий буфером обмена, может подвешивать вставку в других приложениях до разморозки.
- Если процесс общий для двух пространств (например, обычный неизолированный VS Code), его окно прячется, а сам процесс не замораживается.
- Комбинацию, которую уже заняло другое приложение, зарегистрировать нельзя; трей сообщит, какую именно. `Ctrl+Alt+цифра` используется некоторыми методами ввода и играми.
- Windows может не пустить окно на передний план, если переключение запущено фоновым процессом; окна при этом всё равно показываются, только фокус может остаться на прежнем месте.
- Уведомления «где я остановился» и о ветке это всплывающие уведомления значка в трее. Кнопки в них нет (для неё нужна библиотека Windows-toast, которой среди зависимостей `ws` нет); действие находится в меню трея.
- Последняя команда в заметке известна только для оболочек, запущенных через `ws` при установленном хуке. Другие терминалы и оболочки не PowerShell ничего не добавляют; заголовок окна при этом записывается.
- Окнами, запущенными от администратора, обычный `ws` управлять не может: такие элементы помечаются `uncontrollable`, выводится предупреждение.
- UWP/Store-приложения обрабатываются как generic и могут управляться не полностью.
- У изолированного VS Code свои настройки (копия из основного профиля при первом запуске) и свои входы в аккаунты.
